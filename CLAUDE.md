## Project state

ProjectSH is a **Unity 2022.3.62f2 (LTS)** project on the **Universal Render Pipeline (URP 14.0.12)**. It is currently a near-empty project bootstrapped from Unity's URP template — the only code present is the template's tutorial readme (`Assets/TutorialInfo/`), which is boilerplate and safe to delete once real development begins. Game code does not exist yet.

Not a git repository.

## Layout

- `Assets/` — all project content. Currently: `Scenes/SampleScene.unity`, URP `Settings/` (renderer + quality assets), `UniversalRenderPipelineGlobalSettings.asset`, and the disposable `TutorialInfo/` template.
- `Packages/manifest.json` — package dependencies. Add Unity packages here, not by hand-editing csproj.
- `ProjectSettings/` — engine config (input, physics, tags, quality, graphics). `ProjectVersion.txt` pins the editor version.
- `Assembly-CSharp.csproj` / `Assembly-CSharp-Editor.csproj` / `ProjectSH.sln` — **generated by Unity**. Do not edit by hand; they regenerate on Unity focus / import.
- `Library/`, `Logs/`, `UserSettings/` — local caches, not source. Never edit; should not be committed.

## Working in this project

- Unity owns the build. There is no CLI build/lint step in the repo — open the project in the Unity Editor (matching version `2022.3.62f2`) and use **File > Build Settings** to build, **Play** to run.
- Editor scripts (anything under an `Editor/` folder, e.g. `TutorialInfo/Scripts/Editor/`) compile into the editor assembly and run only in-editor, not in builds.
- C# scripts live under `Assets/`. New runtime code with no explicit asmdef compiles into `Assembly-CSharp`; editor code into `Assembly-CSharp-Editor`.
- Every asset/script has a sibling `.meta` file holding its GUID. When moving or renaming via tools (not the Unity Editor), move the `.meta` with it — orphaned/missing meta files break references.

## Tests

`com.unity.test-framework` is installed but no tests exist yet. Run tests via the Unity Editor **Test Runner** (Window > General > Test Runner), EditMode or PlayMode. Test assemblies require an `.asmdef` referencing the test framework; create one under a `Tests/` folder before adding tests.
